# Очередь выступлений

Игроки записываются на выступления во время стрима, организатор вызывает их на матчи. Источник правды - PostgreSQL,
страницы получают изменения по уже существующему WebSocket `/api/ws/overlay`.

## Правила очереди

- **Порядок.** Новая запись встаёт за всеми, кто ещё не выступал в сессии, но перед теми, кто уже выступал.
  Выступавшие и вернувшиеся после выхода (счёт выступлений сохраняется) встают в самый конец.
- **Вызов.** «Вызвать следующего» приглашает первого по порядку; вызванный встаёт в начало списка и подтверждает
  готовность. Для команды 2×2 подтверждать должны оба игрока. Время на подтверждение настраивается (10-600 с)
  и только показывает таймер: никто не исключается автоматически.
- **Матч.** На матч выходят две записи (или одна - настройка сессии). Матч: подготовка → в эфире → завершён.
  После завершения обе записи уходят в конец очереди, у них растёт счётчик выступлений. Отмена матча возвращает
  вызванных в ожидание без «выступления».
- **Пропуск.** Организатор пропускает запись: она получает метку «Пропущен» и уходит в конец своей группы
  (не выступавшая - за всеми не выступавшими, выступавшая - в самый конец). Пропуск вызванного, который не подтвердил
  готовность, пишется в журнал как неявка. Можно исключить из сессии вместо переноса. «Вернуть» ставит пропущенного
  следующим на вызов или на указанную позицию.
- **Ручной порядок.** Организатор переставляет запись на позицию; ждущую нельзя поставить перед вызванными.
  Если передать `rev`, а очередь за это время изменилась - отказ 409, чтобы не перетереть чужую правку.
- **Игрок** может записаться один раз за сессию, выйти (кроме эфира) и подтвердить готовность. Выход одного из
  команды убирает всю команду. Кто действует - берётся только из входа, не из тела запроса.
- **Состояния сессии:** запись открыта / закрыта (вызовы идут) / приостановлена (нет ни записи, ни вызовов) /
  завершена (только просмотр). Организатор добавляет и удаляет вручную при любом состоянии, кроме завершённой.
- **Форматы.** Очереди 1×1 и 2×2 идут отдельно: живая очередь одного формата - одна. 2×2 записывает готовую команду
  из таблицы `teams`; игрок видит свои команды и может записать только их. Формат сессии меняется, пока очередь пуста.
- **Жетон «Без очереди»** порядок не меняет: у записи показывается значок, переставлять её или нет - решает организатор.

## Таблицы (миграция `0047_queue.sql`)

| Таблица | Что хранит |
| --- | --- |
| `queue_sessions` | сессия: название, формат, состояние, настройки, ревизия `rev`. Одна живая на формат (частичный уникальный индекс) |
| `queue_entries` | место в очереди: статус, позиция, счётчики выступлений и пропусков, таймер вызова. `UNIQUE (session_id, position) DEFERRABLE`, позиция есть только у стоящих в очереди |
| `queue_entry_members` | игроки записи (один или двое). Частичный уникальный индекс не даёт игроку стоять в сессии дважды; флаг `active` сбрасывает триггер при выходе записи |
| `queue_matches` | матчи сессии; не больше одного в подготовке или в эфире (частичный уникальный индекс) |
| `queue_match_entries` | стороны матча с именем, MMR и игроками на момент вызова - история не меняется от переименований |
| `queue_events` | журнал: запись, выход, вызов, подтверждение, пропуск, неявка, перестановка, действия над сессией и матчем |

Все изменения идут одной транзакцией под `SELECT … FOR UPDATE` строки сессии, затем `rev + 1`. Порядок пересчитывается
на бэкенде (`store/queue_order.go`) и записывается целиком; уникальность позиций проверяется в конце транзакции.
Память сервера состояния очереди не хранит - после перезапуска всё читается из базы.

## API

Чтение открыто всем, ответы без кэша. Действия игрока - вход обязателен (лимит 30 действий в минуту).
Остальное - роль `superadmin`, проверяется на сервере. Каждое изменение отвечает свежим состоянием.

| Метод и путь | Кто | Что делает |
| --- | --- | --- |
| `GET /api/queue?format=1x1\|2x2` | все | состояние живой очереди: сессия, список, текущий матч, история, `me` для вошедшего |
| `GET /api/queue/sessions` | все | все сессии |
| `GET /api/queue/sessions/{id}` | все | состояние любой сессии, в том числе завершённой |
| `POST …/{id}/join` `{teamKey?}` | игрок | записаться (для 2×2 - своей командой) |
| `POST …/{id}/leave` | игрок | выйти |
| `POST …/{id}/confirm` | игрок | подтвердить готовность |
| `POST /api/queue/sessions` `{title?, format, confirmTimeoutSec?, matchSize?}` | организатор | открыть сессию |
| `PATCH …/{id}` | организатор | название, формат, время на подтверждение, размер матча |
| `POST …/{id}/mode` `{action: open\|close\|pause\|resume}` | организатор | запись и пауза |
| `POST …/{id}/finish` | организатор | завершить сессию |
| `POST …/{id}/call` `{entryId?}` | организатор | вызвать следующего или конкретную запись (команду) |
| `POST …/{id}/entries` `{userId?\|teamKey?}` | организатор | добавить вручную |
| `POST …/{id}/entries/{e}/confirm` | организатор | подтвердить готовность за игроков |
| `POST …/{id}/entries/{e}/skip` `{mode: end\|remove}` | организатор | пропустить / исключить |
| `POST …/{id}/entries/{e}/return` `{position?}` | организатор | вернуть пропущенного |
| `POST …/{id}/entries/{e}/move` `{position, rev?}` | организатор | переставить |
| `DELETE …/{id}/entries/{e}` | организатор | убрать |
| `POST …/{id}/match/start` `{force?}` | организатор | выпустить в эфир (без `force` - только когда все готовы) |
| `POST …/{id}/match/finish` / `…/match/cancel` | организатор | завершить / отменить матч |
| `GET …/{id}/events` | организатор | журнал сессии |

Коды: 400 - неверные данные, 401 - нет входа, 403 - нет прав, 404 - не найдено, 409 - не подходит состоянию очереди
или очередь изменилась, 429 - слишком часто.

## Реальное время

После каждого изменения сервер шлёт в тот же `ws.Hub` сообщение `{"type":"queue","sessionId","format","rev"}`.
Клиент оверлея пропускает незнакомые типы, поэтому OBS не затронут. Страницы `/queue` и `/admin/queue` по сообщению
перечитывают состояние; кадр можно потерять, поэтому есть опрос (12 с, при разрыве - 4 с), перечитывание при
возврате на вкладку и при переподключении. Более старую ревизию клиент не принимает.

## Интерфейс

- `/queue` (только дизайн «Поверхность», как пояс и итоги сезона): текущий матч, список, блок игрока, история.
  `?format=2x2` - другой формат, `?session=<id>` - завершённая сессия.
- Кабинет, раздел «Очередь» (`/admin/queue`): сессия и настройки, матч, список с действиями, ручное добавление
  (`/match-players`, `/match-teams`), история матчей и журнал.

## Конфигурация

Новых переменных окружения и зависимостей нет. Миграция накатывается при старте сервера.

## Тесты

`go test ./...` без базы пропускает интеграционные тесты. С базой:
`RESPECT_TEST_DB=postgres://respect:respect@localhost:5433/respect_it?sslmode=disable go test ./...`
Очередные тесты берут advisory-блокировку и идут по одному (живая очередь формата глобально одна), поэтому нужна
отдельная база, а не рабочая. На совсем пустой базе первый прогон двух пакетов может упасть на гонке миграций -
повторите его.
